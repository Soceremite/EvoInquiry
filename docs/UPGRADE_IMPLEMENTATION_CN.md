# EvoInquiry 项目治理升级实施计划

本次按项目治理升级设计（2026-10-12 修订版）实施。
起点为正式版 1.0.0，提交 `69cfbc5dc5fc34c4d7e6146fe66f5520866f7dfe`。
本计划中的 1.1.x、1.2.x、1.3.x 是交付顺序建议，不表示已经发布。

六个切片的本地源码实施已完成。实际结果、平台限制及证据范围见
[升级验收记录](UPGRADE_VALIDATION_CN.md)，日常操作见
[治理使用指南](GOVERNANCE_USAGE_CN.md)。

| 顺序 | 修改范围 | 可运行验收 |
| --- | --- | --- |
| 1 身份与引用 | 统一 `state_paths.py`；项目、实验、执行、产物、环境和消费者 schema；共享校验、摘要与本地锁 | 新项目仅写 `.ei`；旧根禁止静默写入；双根冲突；固定引用摘要和事务幂等 |
| 2 项目治理 | `project_registry.py`、`artifact_registry.py`；只读盘点、双布局、CAS 发布、恢复、迁移与回滚；新增 project-governance | 预演零写入；并发 revision 均保留；正文、事件、别名和投影各阶段中断；状态 ID 和审查语义保留 |
| 3 文档与复用 | 三份共享契约中的治理与复用部分；公共接口说明；`code_map.py`；两个方法共用数据协议 | 可定位符号、调用者与测试；实现或说明改变可检出；方法处理差异单独配置 |
| 4 环境维护 | `environment_registry.py`；候选 diff、实际探测、分层回执、消费者、lease/pin；新增 environment-maintenance | 不变复用；失败候选不改变旧环境；排队/运行不能重绑；过期 lease 必须核对；unknown 和论文 pin 阻止退休 |
| 5 既有链路 | 固定 spec、执行快照、失败/恢复身份；plan→bridge→queue/run→analyze→audit→paper；Python、shell、模板和安装镜像的命名空间接入 | 修改 checkout 不改变快照；同种子失败和重试均保留；固定纳入规则；现有门禁与检查点回归 |
| 6 全链回归 | 六个种子槽位、至少七次真实轻量 CPU 执行；并发/崩溃/迁移回滚矩阵；目录索引、保留契约和安装包检查 | 报告固定版本；过期别名可诊断/恢复；无活动 `.aris` 默认值；镜像一致；实际测试有回执 |

保留原 84 个技能入口，新增 2 个独立入口，总数 86。治理工具记录身份和证据；
`run_state.py` 继续协调原工作流，队列继续调度原任务，检查点工具继续负责权重保留。
新增契约不把 schema 通过、文件存在或同模型复核转换为科研 accepted。

新运行状态使用 `.ei/runs`，不改工作流 ID。没有 project.yaml 的普通项目仍可工作。
默认产物布局为 compat-v1；governed-v1 须主动选择。正式分析和论文使用固定引用，
current 只做导航。迁移不搬动阶段目录，不全局替换历史证据内容，不删除旧证据。

验证使用本仓库的临时试点，记录命令、环境、退出码、固定输入和输出摘要。
升级不会自动迁移其他研究项目或改动实际共享环境。后续验收在明确授权范围内执行了插件切换与回滚、短 GPU 训练和独立候选安装。真实项目迁移、环境清理和对外发布继续依据各自任务的授权范围和可核对回执。
