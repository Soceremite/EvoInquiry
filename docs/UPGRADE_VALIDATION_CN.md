本次宿主完整回归为 **955 通过、35 跳过、0 失败**（506.46 秒）。此前受限沙箱完整尝试有 9 项失败：3 项归档复制不能保留源文件所有者，6 项本地 HTTP/浏览器监听受限；实际 stderr 和失败 XML 原样保留，未修改这些原有功能来绕过检查。最后的 UTF-8 探测流及中文日志补强单独验收为 17 通过、1 个 Windows 用例跳过（13.76 秒）；最终提交由平台 CI 完整执行。Windows 25 项、expect 4 项、缺少凭据的 MiniMax 4 项及主管理解释器缺少 PyTorch 的 2 项在本机跳过；不把此前 GPU/CPU 检查点试点重复累加为本次执行。

以下保留 **beta.1 来源的升级验收记录**，其中 GPU、依赖冲突、行为评测和安装数字属于此前来源；没有将这些历史试点重新记为 beta.2 执行。

前版交付为 1.1.0-beta.1，起点为正式版 1.0.0，提交 `69cfbc5dc5fc34c4d7e6146fe66f5520866f7dfe`。六个源码实施切片已完成，并补充实际插件切换、GPU 训练恢复、独立候选安装、存储探测及自然语言行为验收。版本保持 beta，部署边界见下文。

| 发布与迁移 | 不可变正文、事件日志、current CAS、投影恢复、预演、迁移备份及布局回滚 | 旧状态不会静默覆盖，普通项目无需主动迁移 |

| 环境维护 | 真实解释器探测；四层实际回执；独立候选；不可变绑定、lease 与复现 pin | 工具负责登记及核验；实际依赖求解仍由现有环境管理器执行 |

2026-10-12 首轮完整回归为 900 通过、21 跳过、0 失败（950.88 秒）；最后一次项目虚拟环境补强后，全部 52 项受影响的治理检查通过。独立 PyTorch CPU 检查点测试 54 项通过。首轮原始回执及失败日志保留，不能当作之后所有改动的认证。

2026-10-13 最终完整回归为 908 通过、23 跳过、0 失败（418.94 秒），另行使用 PyTorch 解释器完成 54 项 CPU 检查点测试（17.92 秒）。本机跳过项为 Windows 13 项、交互终端 4 项、缺少凭据的 MiniMax 4 项及主管理解释器未安装 PyTorch 的 2 项；PyTorch 的两项分别通过独立 CPU 和真实 GPU 测试补充验证。完整集不重复累加安装或治理子集的数量。主测试管理解释器与训练解释器独立，两个原有解释器均未更改依赖。

平台修复的本地受影响回归为 88 通过、14 跳过、0 失败（99.30 秒），覆盖安装选择、真实环境/执行、文件系统、保留契约、镜像、发布参数和行为评估器。该子集包含已跑过的检查，不能与完整集相加；Windows 与 expect 跳过项由对应 CI runner 验收。安装指针要求规范路径与真实目录身份相同，兼容 macOS `/var` 别名；环境导入检查记录模块来源，兼容 Windows 内建 `math` 缺少 `__file__` 的情况。四层验证及失败候选拒绝规则保留，CI 会展示实际失败层、命令、退出状态及日志。

H100 上执行了两种方法、三个种子（11、22、33）。五个主尝试直接完成；method-b/22 在第 12 步实际退出 17，保留失败记录与有效检查点，再以独立 `resumed_from` 身份完成第 24 步。共七个主尝试，六个成功种子槽位，按预声明 first-success 规则统计。恢复所需检查点作为固定历史输入保留。

另一份独立 spec 运行同方法/种子的连续训练对照，不参与主实验的槽位统计或择优。恢复与连续训练的模型、优化器、调度器、Python/CPU/CUDA 随机状态及验证损失逐项相同。检查点预算 512,000 字节，实际完整保存峰值 63,232 字节；PyTorch 记录的张量显存峰值 68,206,592 字节，不包含驱动上下文。训练完成后实际移除了非依赖恢复点，保留已验证的 best/final 权重。

两张 H100 均执行了实际八元素 CUDA 数值探测。以上验证单卡短训练和工程闭环，不认证多卡/分布式训练、大规模性能、跨 GPU 逐位复现或科研主张。

## 存储与平台边界

只读检查不创建项目状态、锁或探测文件。显式 probe 只创建随后删除的自有临时目录，实际核验跨进程排他、释放/重获锁、文件 fsync/replace/读回及 POSIX 目录 fsync。

本会话 QuarkFS 项目挂载实际接受了冲突 flock，提高运行权限也未修复语义，治理写入在创建 `.ei` 之前停止。Overlay 与 XFS emptyDir 探测通过；前者是容器层，后者随 pod 生命周期变化。发现的主机 XFS bind 为只读，没有可写且保留期限已确认的正式卷。因此提供经过测试的诊断及持久部署要求，未声称本机已经完成生产存储部署。正式项目必须由操作者选择持久、支持所需锁及 rename/fsync 的完整项目卷；见[部署指南](DEPLOYMENT_GUIDE.md)。

发布门槛包含 Linux/macOS 完整回归，以及 Windows 两种 PowerShell 的原生安装、本地文件系统和项目→环境→执行→报告流程。Linux runner 安装 expect，以实际执行交互终端用例。Windows 的目录 fsync 与 POSIX 检查点工具、真实 SSH/screen 队列、跨主机网络文件系统、实际断电恢复和可选外部评审 API 仍有独立验收边界。依赖元数据指纹不能完全检出同版本第三方包被外部改写，正式环境实例仍需部署方保持不变。
