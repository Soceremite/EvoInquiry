# 1.6.0 职责冗余与训练停止实测

日期：2026-10-21。对象是当前本地开发工作树；未提交、推送或发布。
本文件保留初次审查与短程测试的观察；后续各节分别记录功能收敛、小时级验证和新增停止连接，不能将旧观察当作新实现的结果。
使用 `experiment-audit` 做本地证据审查，并按 `run-experiment`、`training-check`
的适用规范执行受控验证。没有独立审计裁决，也没有修改运行工具或 skill 正文。

## 功能冗余判断

检查了 89 个 Codex 入口的描述、目录与文本重复候选，并阅读主要重叠组的
职责及流程。去除 frontmatter 和共同原则块后，没有完全相同的正文；这不能
证明没有语义冗余，也没有测量隐式选择准确率。当前建议如下：

| 入口或能力组 | 判断 | 建议 |
| --- | --- | --- |
| `auto-review-loop` / `-llm` / `-minimax` | 评审—修复—复评规范重复；恢复规范已有差异。基础入口要求保持 run ID，MiniMax 入口仍写有超过 24 小时删除状态重开。 | 优先共享循环、证据闭合及恢复规范，保留后端适配与兼容名称；恢复时核实实际工作及原预算。文本差异不等于本轮已复现运行故障。 |
| `paper-poster` | 已弃用，只转发到 `paper-poster-html`，没有独立产出能力。 | 保留旧调用兼容；新请求优先使用 HTML 入口。 |

## 真实 CUDA 停止测试

在一张空闲 H100 上运行真实 PyTorch 前向、反向与优化器更新，两个执行均有
100 万步目标，使用冻结源码、配置和已验证的现有环境。人为放慢循环以便
观察控制行为；这是几分钟的工程故障注入，不是完成百万步或小时级自动科研。
每个执行的恢复存储预算为 1 MiB，保留最新两个有效完整状态。

| 操作 | 直接观察 | 能支持的结论 |
| --- | --- | --- |
| 第 480 步请求普通回顾 | 随后仍有训练更新 | 回顾门限制后续派发，不中断当前进程。 |
| 第 780 步调用 `research_control.stop` | 训练继续，新的 action 申请返回 `Cannot dispatch: RECONCILE` | STOP 记录不执行进程停止；保留活跃 reservation 的行为符合现有契约。 |
| 第 1360 步后注入 NaN，监督脚本在第 1370 步观察到非有限 loss，并显式发 TERM/KILL | 信号到启动器返回约 0.400 秒；主进程及忽略 TERM 的同组子进程均停止；第 1300 步检查点加载后成功执行一步 GPU 更新 | 显式停止有效。本轮快速检测由测试监督脚本提供，不是内置常驻 watchdog，也不是模型自主诊断验收。 |
| 独立执行设置启动器 `timeout=180` | 进程启动到终态回执 180.226 秒，第 3220 步停止，主/子进程均停止；第 3200 步状态成功恢复一步 GPU 更新 | 现有 POSIX 启动器在显式配置超时时会真正终止所属进程组。 |

两组各保留 43,366 字节、两个有效恢复点。恢复验证加载了模型、优化器、
调度器和 RNG，并实际继续了一步 GPU 更新；没有与不中断训练对照，因此
不声称逐位相同续训。最后两张 GPU 均为 0 MiB 显存占用。

第一组被外部信号终止，execution 记录为 `failed`、退出码 -15；已记录停止
意图的工作流在结算后为 `STOPPED`。第二组超时由启动器记录为 `stopped`，
结算后工作流为 `READY`：单个任务超时不等于停止整个研究方向。总调用耗时
分别约 96.31 / 191.08 秒，包含启动前环境核对；不能将第二组的额外 11 秒
误算成超时后停止延迟。

## 确认的缺口与改进归属

**当前具备部分停止机制，尚未具备统一默认的自动紧急刹车闭环。**

1. `research_control.stop` 明确只保存意图；启动器等待期间不轮询这个意图。
   在既有执行工具内补充身份绑定的取消请求、实际停止和终止回执；治理工具
   保持预算与状态所有者的角色。普通回顾不应自动杀掉健康训练。
2. `launch_execution` 的 `timeout` 默认是 `None`，不会自动读取 spec 或工作流
   剩余预算。由 `run-experiment` / queue 将任务上限与原剩余预算、收尾预留
   绑定，并保留每次执行的退出、失败和恢复关系，避免靠换执行 ID 重置上限。
3. `training-check` 默认 30 分钟检查训练质量，未构成独立快速故障保护。
   由实现及执行工具接入框架原生检查或小型监督器，按项目策略处理不可恢复的
   数值错误、持续保存失败、存储告急及硬截止时间；平台期和普通噪声仍走科研
   回顾。停止后核实所属主/子进程退出、保留有效恢复状态并结算原 action。

这些改进应落在现有执行与监控职责内，无需增加新的调度 skill。本轮只完成
审查和实测，以上生产行为尚未改动。跨平台进程树、SSH/调度器、多机训练、
大检查点保存中断和小时级模型自主运行均未在本轮验收。

本地原始记录、脚本、源哈希、摘要及运行证据副本保存在忽略目录
`validation/v160/emergency-brake/`，主要摘要为 `observed-summary.json`，

准备阶段 `/lyd` 挂载未通过实际锁互斥检查，工具拒绝初始化；随后改用 `/tmp`
本地文件系统，没有绕过保护。另一次测试脚本遗漏了配置的 `variant` 字段，
快照工具在启动前正确拒绝；已修正测试脚本并保留 `setup-attempt.json`。
这些准备尝试不计作完成训练或生产功能故障。

本轮结束时，上一轮全量回归所记录的 11 个源码身份全部一致；没有因这次
测试改变生产实现。此前 1,325 个测试通过的记录仍然成立，但它不能代替本轮
发现尚缺统一自动紧急停止链路的结论。

## 后续功能收敛与小时级验证

用户随后批准的三项功能优化已完成：评审入口共享循环及恢复规范，保留后端、
旧状态迁移及原门槛；旧海报入口原样转发参数；相邻能力明确主所有者并复用有效
子产物。完整回归为 **1,331 通过、36 跳过、46 个子测试通过**，三条既有警告。

真实 CUDA 训练循环运行 **3,600.004 秒、2,145,720 步**，包含三次预编程工程
回顾。30 次完整状态发布后保留两个恢复点，共 336,100 字节。声明的 NaN 注入
由测试训练代码在反向传播前拒绝，实际执行失败退出；最新状态恢复后，两次
各三步续跑的完整状态哈希一致。工作流已结算为 STOPPED，所属进程全部退出。

这补齐了小模型在 Linux/H100 上的小时级耐久、有限值保护、存储及恢复实测，
**没有补齐上述产品默认统一急停缺口**：保护和监督来自测试代码，里程碑判断
是预编程的，未验证模型自主科研决策。配置的硬超时在这次长跑中没有触发。
具体数据、失败保留及限制见 [完整验证记录](VALIDATION_1_6_0.md#functional-consolidation-and-hourly-run)；
原始终态摘要保存在 `validation/v160/hourly/observed-summary.json`。

## 自动回顾与本地执行停止的后续实现

本节替代“确认的缺口”中关于当前本地启动器不读取 STOP、spec 和工作流剩余
预算的描述；之前的真实观察及小时窗口保持不变。用户批准后，现有控制器增加
可选的已结算 action 数量和时间回顾边界，既有监控调用观察时间边界；触发只
开门，不预设判断。现有本地启动器读取绑定工作流 STOP、身份绑定的单次停止
请求、spec 上限与原剩余派发时间，保存实际终止回执后才允许结算。没有新增
调度 skill、常驻服务或独立状态数据库。

真实 Linux 进程测试已观察到所属主/子进程退出、无关进程继续运行、普通回顾
不杀健康训练，以及收到信号后保存并以 0 退出仍归类取消。独立假设审查暴露
了正常退出取消和独立终止恢复的两条误归类路径，均已修正。最终完整回归为
**1,349 通过、36 跳过、46 个子测试通过**，包括全部 19 项执行治理测试。

补充窗口保留原始一小时上限，**43 分 52 秒**后收尾。真实模型先从固定数据、
源码及逐样本结果识别两个实验组的共同表达能力障碍，决定 REPLAN；严格等时
复测后，另一轮模型回顾决定 STOP。绑定启动器据此停止正在运行的独立工程
验证任务，停止意图到终止回执约 **3.505 秒**；保存后退出码为 0，仍正确归类
为 stopped。最新恢复点的两次各三步续跑状态哈希一致，验证进程正常退出。

两次测试驱动问题均保留：首个后续任务误用更长训练时间，已取消并排除公平
比较；首个恢复验证虽哈希一致，但退出清理超时，未算端到端通过。修正诊断
及有界复验后才记录恢复通过。停止验证的长任务独立标注，不用于模型优劣
比较。四个正式观察及恢复 owner 均已停止，全部所属进程退出，无未结算任务。

这是构造场景、显式引导、同族模型的临时评估，补齐两项本地可观测能力；
不是完整一小时模型自主科研，也不证明普遍规避局部最优或独立科学验收。

这仍不是通用默认 watchdog：数值/保存/存储异常需要框架或现有监控 owner
识别并作出相应操作；旧合约不自动开启新频率。SSH、调度器、多机以及 Windows
子进程树没有因本地 POSIX 实现而获得验收。详见
[补充验证记录](VALIDATION_1_6_0.md#automatic-review-and-local-stop-follow-up)。
