# 每个 session 一份资源预算表

本功能属于 **EvoInquiry 1.6.2**，当前尚未正式发布。

EvoInquiry 在首次安排需要计算或存储资源的研究时，为当前 session 初始化唯一的
资源表。先展示目标主机的资源状态，让用户选择：

| 选项 | 设置 |
| --- | --- |
| 最大可用（默认） | 可见且允许使用的本机 GPU；允许符合资源条件的同卡多任务；CPU、内存、存储按可用容量；单任务 12 小时内自动放行 |
| GPU 独占（涉及 GPU 时） | 其余设置相同，GPU 需要空闲，由原调度器确认分配 |
| 自定义 | 指定 GPU ID/UUID、共享方式、时长、内存和存储额度等 |

初始化不等于已经替用户选择。用户选一次，后续规划、实现、执行、调参、对比实验
与 Goal 续跑都复用这一份表；不再逐个询问是否批准 90 分钟。若用户先前已经明确
选择了相同设置，直接记录该选择。只有超出表内范围才需要新的选择。
单次作业的一核、128 MiB 等需求只是作业估算，不能自动当成用户选择的会话额度；
首次选项默认推荐最大可用，具体作业仍按足够完成任务的资源安排。

唯一记录位于 `<project>/.ei/resource-sessions/<session-id>.json`，表格由该记录
渲染。其他 skill、计划、交接文档只引用它，不复制另一套预算。重连和上下文压缩
保留同一 session ID；新的 session 重新初始化、选择。跨项目时保留原来的表格
所有者与路径。用户更新额度时修改同一份表，保留修订号；不能借更新表格重置
已有实验的有限预算、账目或停止请求。

普通的“先做实验计划、暂不运行”请求，在可写会话中仍要初始化资源表并提供首次
选择，收到回复后再编排依赖资源的详细计划；这不会初始化实验运行环境或启动训练。
只有宿主真正的 Plan 模式或其他
只读限制才采用只读检查，并明确保留待初始化状态。

## 真正用于安排与派发

| 检查 | 安排实验前 | 实验真正启动前 |
| --- | --- | --- |
| 表格 | 读取当前 session 的用户选择和修订号 | 重新读取，不能沿用旧额度 |
| GPU | 确认可用设备、各卡总/已用/剩余显存及利用率 | 重新检测；逐卡检查预计新增峰值，并汇总总显存占用 |
| 同卡多任务 | 判断是否允许共享，估计所有并发任务需求 | 服从现有调度器、租约及任务分配；记录比较环境 |
| CPU / 内存 | 检查 CPU 配额、当前可用内存和任务峰值 | 重新检测，包含数据加载器、缓存、优化器等占用 |
| 数据集 | 复用已有缓存，估计下载、解压及额外副本 | 根据实际目标文件系统剩余空间检查新增峰值 |
| 权重 / 断点 | 采用既有保留策略，考虑完整新保存和并发保存 | 同时检查权重、恢复点、临时文件与保留空间 |
| 时长 | 表内单任务直接安排，超过默认 12 小时才申请提高额度 | 保留用户/实验原有真实超时，避免偷偷扩张 |

“最大可用”是授权上限，不要求用满所有资源。持续 Goal 不新增总时长窗口；多个
表内任务累计超过 12 小时不等于必须续批。用户原有 GPU 限制、资源额度、宿主
Plan/Goal 规则、科研审查、实验公平和存储保留规范继续有效。既有付费服务额度
沿用原授权；默认不新增购买。

资源不足与需要审批是不同状态：显存或磁盘暂时不够时，等待、减少并发或调整
安排即可；不能将一次资源等待直接判为整个 Goal 阻塞，也不能申请后就忽略物理
容量。普通预算检查不打断已在运行的健康训练。

## 使用接口

```text
python <package>/tools/resource_budget.py --root <project> --session <id> init
python <package>/tools/resource_budget.py --root <project> --session <id> select --preset maximum --selected-by <用户选择的记录>
python <package>/tools/resource_budget.py --root <project> --session <id> check --stage plan --markdown
python <package>/tools/resource_budget.py --root <project> --session <id> check --stage launch --request <需求.json> --markdown
```

`CODEX_THREAD_ID` 存在时可省略 `--session`。其他宿主需要传入稳定的会话身份。
`show` 查看同一份表，`check` 会重新读取资源；`--read-only` 不写入状态，适用于
只读规划/监听。派发需求示例（字节数是新增峰值，主机名必须来自实际探测）：

```json
{
  "host": "actual-execution-host",
  "job_seconds": 5400,
  "cpu_cores": 4,
  "ram_bytes": 8589934592,
  "gpus": [{"id": "0", "peak_bytes": 12884901888}],
  "storage": [{
    "path": "/absolute/output-or-data-path",
    "dataset_bytes": 10737418240,
    "weight_bytes": 2147483648,
    "checkpoint_peak_bytes": 4294967296,
    "other_bytes": 1073741824,
    "reserve_bytes": 2147483648
  }],
  "new_spend": 0
}
```

同一文件系统上的多个目录合并计算峰值，避免把一份剩余空间重复分配。已存在的
数据与权重包含在磁盘已用量中，不再作为新增数据重复计费；各目录的现有占用
由数据/权重所有者提供已有清单或针对性测量，不自动扫描整个数据盘。

冻结执行配置通过 `resource_budget.session_id` 与 `resource_budget.request`
绑定该表。已有实验启动器在环境核验后执行实时检查，未通过则保持任务未启动；
同一 session 跨项目时，绑定原表的绝对 `table_root`，避免创建第二份表。当前
session 已有资源表时，该启动器也会拒绝没有绑定表格的新派发。
队列将表格选择、额度例外与容量不足保留为待处理任务，不消耗未启动训练的重试
次数；环境核验后才出现的资源变化也会通过该执行的检查收据返回等待。
治理队列复用同一入口。其他运行器需要接入相同检查。该工具不替代调度器，不
自动覆盖未绑定的旧启动器，也不承诺 GPU 的原子预留或运行中资源硬隔离。

共享规范：[Session resource table](../skills/shared-references/resource-budget.md)。

## Integration review

这次改动通过所有 skill 已有的共享科研规范接入，不新增 skill 或调度器。会话表
只负责资源授权和实时容量判断；实验方案、公平比较、资源账目、训练终态和回顾
仍由原有所有者负责。旧的未绑定执行保持兼容；当前 session 一旦初始化资源表，
原启动器的新派发必须显式绑定它。

发布清单新增资源检查工具、主线与 Codex 共用规范及本页，保留原有文件排除规则。
`tools/skill-contracts.json` 登记发布清单与队列资源等待的定向变更，
冻结基线哈希保持原值。
测试入口：`tests/test_resource_budget.py` 及原执行、协调、发布与镜像回归。

## 本地验证（2026-10-24）

原生会话引导修正前的完整回归：1,410 项通过、39 项跳过、46 个子测试通过，零失败。
包含磁盘不可读与单项修改保留其他限制的资源/队列检查 45 项全部通过；这 45 项
包含在完整回归中，不重复计数。包完整性与 skill 清单验证通过。新模块另在
Python 3.10 下验证了当时的 37 项用例。

真实新建 Codex 会话暴露了普通计划与宿主 Plan 模式的边界歧义，以及首次选择后
没有及时结束本轮的问题。修正后，两个独立线程、四轮交互验证通过：首次选择、
同会话复用、90 分钟自动放行、启动前实时复检、短 CPU 执行和跨会话隔离。
相关资源、队列、镜像与包保留回归 95 项通过。实际 CPU 验证只运行一次，约
0.25 秒完成，退出码 0，保留 6 行指标和 384 条预测。前三次未完成记录全部保留。

追加原生 Plan/Goal 验收通过：Plan 首次选择默认推荐最大可用，保持只读，切回
普通模式后在同一线程保存一份表，90 分钟检查自动放行。Plan 和 Goal 分别监听
约 4 分钟、240 步的真实 CPU 训练并核验自然退出；Goal 只收到一次用户启动，
宿主自动续出第二轮，两轮都正常完成，训练存活时未标记 blocked。最新相关回归
95 项通过。模型与工具开销使部分检查晚于请求的 20–30 秒间隔，未验证硬实时监控。

实际 CPU 实操走通首次待选择、测试用户选择、规划放行、冻结执行、实时资源检查、
启动计算与保存结果。声明的单任务分配为 90 分钟，实际计算很短，并未运行 90
分钟训练。两张本机 NVIDIA GPU 的显存与利用率已实际探测；GPU UUID 传给子进程
的行为有进程级验证，但该测试没有分配真实 GPU 显存。

最终回归与重复实操收据保存在本地忽略的 `validation/release-1.6.2/`，前期记录
保留在 `validation/session-resource-budget/`。收据不包含用户的实际
会话授权。未做原生 Windows/macOS 复测、小时级 Goal/Plan 实测或资源原子预留验证。
这些改动尚未发布。原生会话验收使用隔离安装的修正版；验收后也同步了默认安装：
本地插件源与缓存均为 1.6.2，305 个运行文件与受测版本一致，
原生重新扫描识别 89 个子 skill。旧安装保留了可回退备份；过程见
[1.6.2 验收记录](VALIDATION_1_6_2.md#default-installation-observation)。
